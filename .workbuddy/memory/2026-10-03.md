### 顺带修掉的三个真 bug
1. **标题重复**「雨夜的半音叹息 · 之一 之一」——曲名与 em 标签内容重复；拆成 `n`(曲名)/`v`(版本) 字段。
2. **静态服务不支持 HTTP Range** → 音频能播但**拖动进度条完全无效**。
   已改为 `fs.stat` + `createReadStream` 流式响应 + 206 Partial Content（顺带不再把整首歌读进 Pi 内存）；
   支持 `bytes=N-` / `bytes=-N` / 越界 416，客户端中断即销毁 fd。
3. **Cloudflare 导致 Range 失效**：CF 命中缓存后以 200 整份响应、不透传 Range → 线上拖动无效（直连源站正常）。
   修：音视频响应改 `Cache-Control: no-store`（不走 CDN 缓存）+ 音频 URL 加 `?v=1` 绕开已缓存的旧副本。
   实测经 CF 的 Range 现在返回 206，拖动恢复。

### 一个我自己犯的错（值得记）
把 `audio.preload="metadata"` 插进了 `var player=…, audio=…, playBtn=…` 这条 var 声明的**中间**，
导致 `playBtn` 等变成未声明赋值 → 严格模式 ReferenceError → **整个脚本中断、播放器全空**。
而且我**没先本地复测就部署了**，线上才发现（表现为"曲目列表 []"）。
→ 教训：改完页面脚本必须先本地浏览器复测再部署；不要把语句插进多变量 var 声明中间。
