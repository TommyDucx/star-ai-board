### 第二批实现：Lazy SMP 多线程（search.rs + main.rs）
1. `TranspositionTable` 用 `Arc<RwLock<>>` 共享（probe 读锁 / store+clear+resize+new_generation 写锁）。
2. `Policy` 用 `Arc<Policy>` 共享（predict 只读）。
3. Searcher 加 `threads: usize` 字段 + `set_threads()`；新增 `fork()` 从配置 fork 线程私有实例
   （共享 tt/policy/配置，私有 history/killer/path/nodes）。
4. `search()` 拆成外层调度 + `search_single()`：外层重置 stopped 一次，>1 线程时 spawn N-1 辅助线程
   共享 TT，主线程跑自身实例，最后 join；`stopped.store(false)` 上移避免辅助线程误重置。
5. main.rs 加 `Threads` UCI option（default 1 min 1 max 16）+ setoption 分支。
6. match.py 加 `--threads-a/--threads-b` 参数（UCIEngine 发 `setoption name Threads value N`）。

### 编译/冒烟
- 编译通过（16.5s）；`uci` 上报 Threads option；单线程/4线程 go depth 8、movetime 均正常返回 bestmove。
- 性能：startpos movetime 2000，4线程 918ms 达 depth11（单线程 1308ms）→ 有加速。

### 已知权衡（Lazy SMP）
- 多线程各自 `new_generation()` 会让 TT age 快速递增（u8 wrapping），老化窗口变短、命中率略降，
  但不影响正确性；后续可改为「主线程统一管理 age」优化。

### 第二批验证结果（96 局 / concurrency 2 / movetime 300ms）

- 无崩溃、无非法走法；4线程 918ms 达 depth11（单线程 1308ms）有真实加速。
- 已 commit `2e5817e` + tag `v2_smp`。

## 第三批：重训 Policy（2026-08-13 下午）

### 环境

### 改动（4 文件同步）
1. `train_policy.py`：PolicyNet 加残差块 ResBlock(16→16+shortcut) + FC1 64→96；数据配比
   75%自博弈+25%弃子局、过滤(selfplay ply>90 剔除；lichess attack_score≥10 或战术主题保留)、
   样本加权(进攻×1.6/平局×0.4/lichess普通×1.2)；lr 每12轮×0.25 + per-sample加权loss + 早停(patience 5)。
2. `export_weights.py`：加 res.conv 权重导出（顺序 c1→res→c2→fc1→fc2）。
3. `policy.rs`：加 resw/resb 层 + FC 64→96（predict 加残差推理）。
4. `policy_golden_test.py`：同步 load_bin/rust_forward 复刻。

### 训练结果
- 数据：selfplay 5907 + lichess 1421（过滤后），8×增广 51642 条，权重直方图 1.6:24073/1.0:18048/0.4:2609/1.2:6912。
- 40 epochs，最终 val_top1 0.4233 / val_top5 0.5311（旧版 46%/53%），参数 502,240（2.01MB）。
- golden test 通过：Rust 推理与 ONNX 完全一致（max|Δlogit|<1e-4）。
- 旧 policy.bin 备份为 `policy/policy_old_fp32.bin`；旧引擎二进制 `my-engine_oldpolicy`。

### ⚠️ INT8 量化结论：不值得做（收益可忽略）
- 实测 Policy 单次前向仅 0.12ms；引擎每个 go 只前向 1 次，搜索本身 movetime 300ms → Policy 占比 <0.1%。
- 即使 INT8 提速 2 倍也只省 0.06ms/次。用户方案"INT8→节点数大涨"基于"Policy 每节点前向"误判。
- 结论：跳过 INT8，保留 FP32 单模式（policy.rs 无需双模式）。

  33万→50万但数据未增，40 epoch 可能欠训练/过拟合。

  分辨是哪个因素致弱。

### 第三批最终结论
- 残差 CNN + 数据重构：**未采用**（−40 Elo），回滚。
- INT8 量化：**跳过**（Policy 每步仅 1 次前向 0.12ms，占比 <0.1%，收益可忽略）。
- 当前最优 = v2_smp（Lazy SMP 多线程 +51 Elo + 旧 policy）。

### 消融实验（定位 −40 Elo 主因，用 val_top1 做快速代理）
- **消融1（旧网络无残差 + 新数据过滤加权）**：val_top1 仅 0.3438（旧版 0.46，跌 11.6pp）
  → **数据重构（过滤+加权）是致弱主因**。
- 交叉对比：残差+新数据 0.423 vs 旧网络+新数据 0.344 → **残差 CNN 单独 +7.9pp（有益）**，
  只是被数据重构的负贡献掩盖。
- **消融2（残差+FC96 + 旧数据不过滤不加权）**：val_top1 峰值 0.4150/末值 0.4041（旧版 0.46）
  → **残差 CNN + FC96 单独也是略负贡献（−5.6pp）**。
- 脚本：`policy/ablation1.py`（旧网络+新数据）、`policy/ablation2.py`（残差+旧数据）。

### 消融最终结论（第三批全面否定）
| 组合 | val_top1 | val_top5 | 相对 v2 |
|---|---|---|---|
| v2（无残差FC64 + 旧数据） | **0.46** | 0.53 | 基准（最优） |
| 消融1（无残差 + 新数据过滤加权） | 0.344 | 0.484 | −11.6pp（数据致弱） |
| 消融2（残差FC96 + 旧数据） | 0.404 | 0.537 | −5.6pp（残差致弱） |
| 第三批（残差 + 新数据） | 0.423 | 0.531 | −3.7pp |

- **数据重构（过滤+加权）是主因，残差 CNN+FC96 是次因，两者皆负贡献。**
- 结论：v2 的原始 Policy 设计（无残差 FC64 + 不过滤不加权数据）已是当前最优，无需再改。
- 保持 v2_smp 为最终成果，第三批实验全面否定、已回滚。

## 第五批：自博弈 RL 强化学习闭环（2026-08-13 下午）
