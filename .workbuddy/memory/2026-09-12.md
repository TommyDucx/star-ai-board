## Round 3（主 agent 内联续跑；子 agent 配额仍未恢复）

### 已修 + 已部署（admin.js，线上 md5 与本地一致 `549a0144…`）
1. **[P2] 后台磁盘指标解析错位——生产环境也错**：`getDisk()` 按列位置读 `df -k /` 的 `last[2..5]`，
   但 POSIX 列序是 `Filesystem|1024-blocks|Used|Available|Capacity|Mounted on`，**下标整体差一位**。
   - 树莓派真实值 total 28.7GB / used 18.7GB / free 8.7GB / **69%**，
     后台实际显示 total 18.7GB(=Used) / used 8.7GB(=Available) / free null(→"0 B") / **0%**
     ——**SD 卡已 69% 却显示 0%**。
   - macOS 的 df 还多出 iused/ifree/%iused 三列，percent 读到 **inode 数量**（实测 426864%）。
   - 修复：`df -kP /`（POSIX 强制 6 列）+ 锚定挂载点为 `/` 的行取值。
2. **[P2] 每日任务进度会回退**：`dayActivity()` 按 `prog.attempts` 统计今日已解，而 attempts 只有 30 条上限。
   实测解开 5 关后 `solve-three=3/3`，再制造 30 次提交 → **掉回 0/3**，`report.solved` 5→0，
   **用户当天已解锁的奖励资格丢失**。修复：新增独立字段 `prog.dailySolved={"YYYY-MM-DD":n}`（留 14 天），
   `dayActivity` 优先读它，老数据无字段时回退扫 attempts（向后兼容、无需迁移）。
3. **[P3] `GET /api/tactics/current` 即使 tier 未变也写盘**（mtime 前进；前端 0 调用）→ 改为仅在变化时落盘。

### 本轮重大「通过」结论：账号跨设备同步真的成立
两个独立 cookie jar 模拟双设备，7 项全过：A 解 1 关→B 看到；B 解第 2 关→A 看到（**双向同步**）；
**并发提交同 attemptId** → 一收一 duplicate、连胜只 +1（不重复计分）；改名同步到 B；
「退出其他设备」→ B 立即 401；**10 次并发领同一任务只记一次**（幂等）。
→ 结论：进度/连胜/称号/奖励的账号持久化与跨设备同步**可靠**，且并发无丢更新。
（此前担心的"读-改-写整文件"竞态，在 Node 单线程同步写 + 临界区无 await 的情况下不会发生。）
