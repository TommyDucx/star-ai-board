### 关键发现：P1 修复只「部分有效」，可慢速刷分绕过（**未修，待决策**）
- 实测脚本 `/tmp/qa_residual.mjs`（本地 8801，账号 `qaresid_5uo36r`）：完全不与引擎对弈，
  `start → sleep 5.2s → finish{win, moves:8, metrics 满分}`，稳定 **+4/局**，6 局 1200→1224。
- **量化**：频率上限 20 局/10min ⇒ 约 **+480 分/小时**，无人值守约 3 小时逼近上限 2600。
- **根因**：① `moves` 是纯数值门槛（实测 `"8"` 字符串、`300`、`99999`(钳到300) 全部通过，
  只有传 8 个非法着法数组才被拒）；② `metrics` 仍全信客户端 ⇒ `quality` 保底 +7；
  ③ `createdAt` 虽服务端落盘但只要求 ≥5s，与真实步数无关。
- **重要推论（免得白干）**：把时长下限改成「moves × movetime」**几乎无收益**——
  因为频率上限（每 30s 一局）比时长下限更严，抬高时长下限不改变刷分速率。
  **唯一真杠杆是让服务端看到真实着法**（WS 引擎桥层按 gameId 记录 movelist，finish 时比对）。
- 三档方案（A 校验合法着法数组 / B 时长随步数 / C WS 层记录真实着法）已写入
  `qa/round2-findings-partial.md`，**C 才是根治，A/B 边际收益小**。

### 测试方法学的坑（已补进 `qa/QA_BRIEF.md`，下次别再踩）
1. **`agent-browser network route --abort` 实测无效**（拦截后请求仍 200）——我因此一度得出
   "接口全挂仍优雅降级"的错误结论，已推翻。模拟断网要用 **`set offline on`**。
2. **静态资源有 `max-age=604800`**：把文件改名测"资源加载失败"会被缓存绕过，
   必须用**新会话**（`--session fresh1`）才测得出来。
3. **我自己写的 a11y 扫描脚本连错两版**（用 `innerText` 判 input；判 button/a 时漏 `textContent`），
   产出过假阳性。正确做法：`el.labels` DOM API + `aria-label` + `textContent` 综合判定。
4. **`/tmp/scp.exp` 必须显式传参**，漏传会静默失败但远端仍打印 EXTRACT_OK
   → 部署后**必须比对 md5**（本轮就是这样发现一次上传失败的）。
