# 2026-08-16 工作日志

## Texel Tuning 结果：−61.4 Elo，否定

云 agent 跑了完整 Texel 调参闭环（自对弈 3000 局 → 58040 条安静局面 → 200 epoch Adam → 400 局对弈验证），结果**显著变弱**：

| 项 | 值 |
|---|---|
| loss | 0.185655 → 0.183484（降 ~1.2%，单调但极小）|
| 对弈 | old 213 胜 / 44 和 / tuned 143 胜，tuned 胜率 41.25% |
| Elo | **−61.4**（tuned 更弱），CI [−94.7, −29.3]，LOS 0.01% |

**「攻王过拟合」特征（关键证据）**：
- `katt_knight` +59（3→62）、`katt_pawn` +54（1→55）、`katt_queen` +39（6→45）；
- 子力价值压缩：pawn 100→55、rook 500→445；通路兵低行奖励异常抬高（passed_1 5→64）。
- loss 下降但实战变弱 = 在 self-play 分布上拟合更好 ≠ 搜索中更强。

**根本原因**：eval 是「叶节点估值 + 剪枝阈值」的双重载体，攻王权重膨胀会让引擎在进攻局面误判「已占优」，触发更激进的 null-move/futility 剪枝，过度投入进攻、忽略防守。手工调好的 eval 与剪枝阈值是**耦合系统**，孤立地按 self-play 结果调 eval 会破坏耦合。

## 结论与方向
- **数据/评估驱动的优化在当前 self-play 数据质量下是死路**：eval/policy 已到手工设计局部最优，self-play 分布太窄、且 eval 与搜索耦合，任何按 loss/val_top1 拟合的改动都破坏搜索行为。
- 剩余合法路径 = 搜索侧结构改进（不触碰 eval 语义）：IID（已背书、低风险正向、尚未做）、TT 桶式 + PV 标志（为 IID 和奇异延伸铺路）。
- 长期 NNUE 需要更好的数据管线（多样化教师数据），当前不具备。
